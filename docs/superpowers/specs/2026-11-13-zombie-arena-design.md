# 僵尸竞技场（Zombie Arena）设计规格

- 日期：2026-11-13
- 状态：已通过设计评审，待实现
- 项目路径：`/home/jichi/zombie-arena`

## 1. 目标与范围

做一个在不大地图里打僵尸的单机 roguelite 网页游戏。核心体验是「每波结束用 3 个装备栏做构筑取舍」：5 个武器流派各有不同操作方式与资源，僵尸种类克制构筑，小地图有互动物件与随机事件，每局通过天赋/诅咒走出不同成长路线，局外用点数解锁内容。

**首版一次性实现全部系统**：5 流派、3 格装备（套装/组合技/合成升星）、完整商店经济、7 种僵尸 + Boss、地图互动物件、天气事件、天赋、诅咒契约、角色、局外解锁。平衡与打磨留待后续迭代。

### 已确认的决策

| 项 | 决定 |
|---|---|
| 平台 | 浏览器单页 Canvas 2D |
| 技术栈 | **TypeScript + Vite + ES modules**（`npm run dev` 开发，`npm run build` 出静态 `dist/`；不使用 `file://`） |
| 代码组织 | 按系统分模块，每个模块单一职责 |
| 核心架构 | **声明式规则引擎**（数据表 + trigger/when/effects 规则），另设内置能力原语承载带时间状态的手感 |
| 装备操作 | `1/2/3` / 滚轮切换当前武器 + 鼠标瞄准；WASD 移动，左键使用，R 换弹，右键/长按蓄力或放置 |
| 局长度 | 无尽波次，死亡结算；每 5 波一个 Boss |
| 美术 | 手绘像素风，离屏 Canvas 程序化生成贴图，`imageSmoothingEnabled = false`，零外部素材、零网络请求 |
| 存档 | localStorage，带版本号 |

### 非目标（YAGNI）

- 联机、排行榜、后端服务、账号系统
- 音频（首版仅可选极简 WebAudio 提示音，不做完整音效系统）
- 手柄/触屏操作、移动端适配
- 关卡编辑器、MOD 支持、自定义规则脚本语言
- 复杂物理引擎（碰撞只用圆/矩形简单判定）

## 2. 架构与数据流

### 2.1 目录与职责

```
src/
  main.ts                 启动、RAF 主循环、阶段状态机
  engine/
    events.ts             类型化 EventBus 与事件负载
    rules.ts              Rule 类型、when 谓词组合、优先级、规则注册与求值
    effects.ts            内置 effect 原语（改数值 / 生实体 / 加状态 / 治疗 / 特效…）
    abilities.ts          10 个手感原语 + 资源状态机（弹匣/蓄力/连击/能量/法力）
    rng.ts                按 run 播种的可复现随机（商店/波次/天赋）
  data/
    weapons.ts            5 流派 × 3 件 = 15 件，含星级成长曲线
    zombies.ts            7 种普通 + 2 种 Boss
    rules.content.ts      套装加成、5 个跨流派组合技、天赋、诅咒、天气事件（全是 Rule）
    characters.ts         5 个角色 / 局外解锁表
    shop.ts               商店权重、消耗品、被动道具、价格
    maps.ts               2~3 张小地图布局（路障/油桶/陷阱位）
  game/
    state.ts              RunState 类型与 resolveLoadout()（唯一的构筑结算入口）
    combat.ts             实体、伤害管线、状态与元素反应
    wave.ts               波次导演、预告、Boss 节奏、难度曲线
    economy.ts            商店刷新/锁定/售出/合成/利息
    arena.ts              地图互动物件、破坏、修补、天气事件
    meta.ts               局外点数、解锁、localStorage 存档
  ui/
    input.ts              键鼠输入映射
    render.ts             Canvas 绘制（只读游戏状态）
```

每个模块通过明确的类型接口通信；`data/` 只有数据与规则声明，不含引擎逻辑；`engine/` 不认识具体装备/僵尸；`game/` 把两者组装成玩法。渲染层只读状态，不修改状态。

### 2.2 规则引擎与能力原语

声明式规则是架构主轴：装备、套装、组合技、天赋、诅咒、天气、僵尸特性全部表达为 `Rule { id, trigger, when, priority, effects }`。`when` 支持 `all` / `any` / `not` 组合的基础谓词（当前装备流派、星级、资源阈值、目标标签、波次、天气、随机数等）。effect 按 `priority` 分四阶段执行：**基础值 → 加法 → 乘法 → 覆盖**；同类加法叠加、乘法叠乘、覆盖取最后注册者。

引擎只解释「规则」。带时间状态的操作手感由 10 个**内置能力原语**承载，它们是引擎的一等原语，由流派配置用数据声明引用哪个原语、什么输入、什么资源：

`meleeSwing` / `hitscan` / `projectile` / `chargeSlam` / `placeDeployable` / `spellBolt` / `aoeBurst` / `reload` / `dash` / `detonate`

即：**手感归原语，一切影响数值与触发的东西归规则**。这样既保持声明式，又避免把换弹/蓄力状态机硬塞进 trigger/effect。

### 2.3 核心数据流

```
输入 → 当前装备的流派配置 → abilities 原语
     → EventBus.emit('onHit'|'onCast'|'onReload'|'onHeavy'|'onKill'|'onWaveEnd'…)
     → RuleEngine 求值「当前生效规则集」→ effects 修改 DamageOp / 生成实体
     → combat 提交伤害与状态
     → render 只读状态绘制
```

「当前生效规则集」由 `resolveLoadout()` 在装备/天赋/诅咒/天气任一变化时重算一次：

```
3 格装备 → 星级修正 → 2/3 件同流派套装 → 5 个跨流派组合技
        → 天赋 → 诅咒 → 被动道具 → 天气事件
        → 扁平 ActiveRule[]（顺序确定）
```

战斗热路径只遍历这张扁平表，**不做任何 `if (hasGun && hasMagic)` 特判**。

伤害走**管线**：`onHit` 事件携带可变的 `DamageOp { base, mult, crit, element, tags, target }`，规则在提交前修改它。附魔子弹、破甲、连击加伤、第 5 次施法翻倍、雨天电系加成、持盾正面免疫全部由此实现。`combat.ts` 在管线末尾统一提交伤害、结算状态与元素反应、派发 `onDamage` / `onKill`。

### 2.4 阶段状态机与循环

```
TITLE → CHARACTER_SELECT → SHOP（含下一波预告）
      → COMBAT → WAVE_END（天赋三选一 / 利息结算 / 诅咒契约）
      → SHOP → … → GAME_OVER → META_SUMMARY
```

固定 60Hz 逻辑更新步长；`dt` 钳制（最大 0.05s）防止切标签页回来后穿模；窗口失焦自动暂停并暂停音频/计时。

### 2.5 可复现性

所有随机（商店刷新、波次组成、天赋三选一、天气、暴击）经 `rng.ts` 的播种 RNG，每个 run 一个种子，可记录在结算页以便复现 bug。同样的构筑与种子永远得到同样结果 —— 这也是纯逻辑层单测的基础。

## 3. 装备、流派手感与 3 格策略

### 3.1 15 件武器

每件从 **★1 起**，最高 ★3；星级提升基础伤害/弹匣/冷却等，并在 ★2/★3 解锁额外规则条目。

| 流派 | 3 件 | 独特资源 / 输入手感 |
|---|---|---|
| 刀 | 短刀 / 武士刀 / 链锯 | `combo` 连击数：左键近身快速挥砍，每层 +12% 伤害（上限 10 层），**挨打清零**；链锯为按住持续伤害 + 过热条 |
| 枪 | 手枪 / 霰弹枪 / 狙击枪 | `ammo` + 换弹状态机：R 换弹（1.1~2.2s），空仓自动换弹；霰弹扇形多弹丸、狙击穿透 + 开镜减速 |
| 棍棒 | 球棒 / 铁锤 / 狼牙棒 | `charge`：按住左键蓄力（0~1.2s），松开释放扇形重击，蓄满附带 0.8s 眩晕 + 范围击退；轻点只有轻击 |
| 科技 | 自动炮塔 / 电网 / 无人机 | `energy` 自动回复：右键在鼠标位置放置（有距离上限、场上数量上限），炮塔/无人机自动索敌持续存在，电网是地面持续区域；换弹概念替换为「重新部署冷却」 |
| 魔法 | 火球杖 / 冰霜法典 / 雷电戒指 | `mana` 自然回复：左键施法，元素状态叠加（火=灼烧 DoT、冰=减速层数→冻结、雷=导电层数→连锁）；不同法杖基础元素不同 |

`1/2/3` 或滚轮切换当前武器。**每个格子独立保存自己的资源状态**（弹匣、连击、蓄力、能量、法力），切回来时状态还在 —— 让「多带一把枪当备用弹匣」成为真实策略。

### 3.2 3 格策略的三层规则（全部是 Rule 数据）

1. **同流派套装**：2 件同流派 = 小加成；3 件 = 大加成。
   - 刀：2 件连击上限 +4；3 件挨打不清零而是减半
   - 枪：2 件弹匣 +2；3 件换弹速度 +30%
   - 棍棒：2 件击退距离 +25%；3 件蓄力速度 +40%
   - 科技：2 件能量回复 +25%；3 件部署上限 +2
   - 魔法：2 件法力回复 +25%；3 件每第 5 次施法免费且伤害 ×2

2. **跨流派组合技**（5 个，装备栏里同时存在两流派即触发）：
   - 枪 + 魔法 = 附魔子弹：弹丸带当前元素层
   - 棍棒 + 科技 = 电击棍：重击释放连锁电弧
   - 刀 + 魔法 = 吸血刃：近战击杀回血
   - 科技 + 魔法 = 符文炮塔：炮塔发射法术弹
   - 枪 + 科技 = 智能瞄准：子弹弱追踪

3. **合成升星**：购买同名 → 该格 `star = min(3, star+1)` 并重算规则集；已 ★3 再买则改为返还金币，不消耗格子。

### 3.3 被动格与消耗品

- **被动格 3 个**（不占武器栏）：移速鞋、护甲、暴击镜、回血符等，规则同样进 `resolveLoadout()`。
- **消耗品**（血包、手雷、一次性护盾）走 `Q` 快捷使用，不进装备栏， stacked 数量显示。

### 3.4 规则冲突与结算顺序

`resolveLoadout()` 每次重算后产出**顺序确定**的扁平数组；配合播种 RNG，同样的构筑永远得到同样的结果。所有 effect 严格按 4 个优先级阶段执行，避免「先乘后加」歧义。

## 4. 商店、经济与波次

### 4.1 商店

- 每回合随机刷出 **4~5 件**，权重随波次与所选角色偏移。
- 刷新 2 金（每回合首次刷新免费）；**锁定**单件留到下回合；售出返还 **50%** 金币。
- 价格按稀有度 **3 / 6 / 10** 金；装备、被动道具、消耗品共用一个商店池。
- **波次预告**：商店阶段显示下一波主要僵尸类型（如「奔跑者 + 持盾」），并让商店权重向克制装备倾斜，使购买有针对性。

### 4.2 经济

- 击杀掉金：普通 1、**精英 3**、Boss 15。精英指标记了 `elite` 的装甲僵尸与召唤者（血量 ×1.6、体型更大，行为不变）；Boss 波的小怪不额外掉金。
- 波次结算基础奖励：`5 + 波数`。
- **利息**：`floor(gold / 10)`，上限 5 金，在波次结束时结算。
- **诅咒契约**与利息形成「现在变强 / 攒钱等大件 / 主动加难度换收益」三角。

### 4.3 僵尸（7 种普通 + 2 Boss）

| 僵尸 | 特性 | 克制的构筑 |
|---|---|---|
| 普通僵尸 | 慢而多，铺垫 | — |
| 奔跑者 | 速度快、血少 | 惩罚不够灵活的远程站桩 |
| 胖子 | 血厚，死亡爆炸 | 惩罚贴脸近战 |
| 持盾僵尸 | 正面免疫子弹 | 需绕后 / 魔法 / 棍棒击退转身 |
| 吐酸僵尸 | 远程弹 | 逼玩家持续移动 |
| 召唤者 | 持续生成小怪，高优先级标记 | 必须优先击杀，惩罚无 AOE 构筑 |
| 装甲僵尸 | 高减伤 | 怕棍棒 `breakArmor` 标签破甲 |

**Boss**（每 5 波一只，交替）：巨型屠夫（冲锋 + 范围击退）、尸潮之母（持续召唤 + 毒池）。

**难度曲线**：数量与血量随波数递增（无尽），每 5 波 Boss 波替换常规组成；速度不随波数无限增长（避免不可闪避）。僵尸特性以 `Rule` 声明（如持盾的 `when: hitFromFront && damage.tag === 'bullet'` → `effect: negate`）。

### 4.4 小地图与事件

- **尺寸**：约 960×640 逻辑像素，单屏，四周围墙；玩家不能离开边界。
- **互动物件**：可破坏路障/木门（波间花钱修补以制造通道）、可引爆油桶（枪/魔法远程打爆，产生火焰地面）、电箱（雨天导电）、科技专用陷阱位（地雷加成）。
- **每波随机一个天气/事件**（挂在 `onWaveStart` / `onHit` 上的 Rule）：
  - 夜晚：视野遮罩（径向渐变 + 灯光半径）
  - 雨天：电系伤害 +30%、电箱导电
  - 起火：地面燃烧蔓延，持续伤害区域
  - 毒雾：从边缘逐渐缩圈，圈外持续掉血
- **地图 2~3 张**：布局（障碍/油桶/陷阱位）不同，由局外解锁。

### 4.5 角色成长与风险选择

- **天赋**：每回合结束从 3 个随机天赋里选 1，可叠加；约 14 种（暴击率 +10%、击杀回血、炮塔数量 +1、法力回复 +25%、换弹 -20%、移速 +8%、近战范围 +15%、元素层数上限 +1、利息上限 +2…）。
- **诅咒契约**（可选 1 个/回合，换取额外金币或稀有装备）：僵尸移速 +20%、商店涨价 25%、Boss 提前、玩家受伤 +15%。契约持续整局且可叠加。
- **5 个角色**，开局选择，各偏一个流派：老兵-枪、巫师-魔法、工程师-科技、浪人-刀、狱卒-棍棒。角色效果为一套初始 Rule + 商店权重偏移。

### 4.6 局外进度

死亡按 `波数 × 2 + 击杀 / 10 + Boss 数 × 5` 结算点数；localStorage 存档。点数解锁：新装备进入商店池、新角色、新地图。存档结构带 `version` 字段；读到不兼容版本时安全重置并提示，不崩溃。

## 5. 错误处理与测试

### 5.1 错误处理

- 存档损坏 / 版本不符 → 安全重置并提示，不崩溃。
- `dt` 钳制 + 失焦暂停，防止切换标签页后穿模与状态跳变。
- 规则求值中的未知 effect id / 非法谓词 → 开发模式下抛出明确错误，生产模式下跳过并 `console.warn`，不让单条坏规则冻结整局。
- 实体数组统一延迟删除（标记 `dead` 后在帧末清理），避免遍历中删除导致漏怪。

### 5.2 测试策略（Vitest，纯逻辑层不依赖 DOM/Canvas）

| 模块 | 覆盖点 |
|---|---|
| `resolveLoadout` | 套装 2/3 件、5 个组合技、星级修正、优先级顺序、被动格 |
| `rules.ts` | `when` 组合（all/any/not）、effect 四阶段顺序、覆盖类冲突 |
| `economy.ts` | 利息上限、售出 50%、同名合成升星 / ★3 返还、刷新与锁定 |
| `wave.ts` | 波次预告与实际组成一致、每 5 波 Boss、难度曲线单调 |
| `combat.ts` | 持盾正面免疫子弹、破甲、元素反应（灼烧/冻结/连锁）、吸血刃 |
| `meta.ts` | 存档版本迁移 / 损坏重置 |
| 渲染 smoke test | 首帧启动不抛错 |

### 5.3 验收标准

`npm run dev` 后可在浏览器里完成一局：选角色 → 看预告 → 商店购买/刷新/锁定/售出/合成 → 战斗（5 流派手感可辨、组合技可见）→ 天赋三选一 → 遇到克制型僵尸与天气事件 → 每 5 波 Boss → 死亡结算点数 → 解锁内容在下一局生效。`npm run build` 产出可静态部署的 `dist/`，`npm test` 全绿。
